\begin{abstract}
\noindent
We benchmark every numerically-evaluable special function in \textbf{Mathilda}
(\sfncases{} heads) against three external systems --- \textbf{Python} (SciPy for machine
precision, mpmath for arbitrary precision), \textbf{Maxima}, and \textbf{Mathematica}
(via \mcode{wolframscript}) --- across three regimes: machine-real, complex, and
arbitrary precision (\sfapdps{} digits). Two things are measured: \emph{speed} (per-call
scalar latency in every regime, plus machine-real vectorized throughput over a
$10^6$-element buffer), and \emph{accuracy}, defined \emph{oracle-free} as the number of
leading significant digits to which the engines mutually agree, with any engine that
falls out of the consensus flagged. The sweep is self-contained --- it does not touch the
weekly \mcode{run\_all.py} gap gate --- and regenerates this document's tables from one
results JSON.
\end{abstract}

\section{Method}

\paragraph{Engines and versions.}
\begin{itemize}\itemsep1pt
  \item \textbf{Mathilda} --- \sfmathilda{}.
  \item \textbf{Mathematica} --- \sfwolfram{}, driven by \mcode{wolframscript -file}.
  \item \textbf{Maxima} --- \sfmaxima{}.
  \item \textbf{Python} --- \sfpython{}. SciPy's \mcode{scipy.special} (compiled C) backs
        the machine-real and complex columns; mpmath backs arbitrary precision (SciPy is
        double-only) and is also the fallback for the handful of heads SciPy lacks.
\end{itemize}
Platform: \sfplatform{}.

\paragraph{The three regimes.}
Each head is exercised at (MR) machine-real arguments, computed to IEEE double;
(C) complex machine arguments; and (AP) exact-rational arguments evaluated to \sfapdps{}
digits. In Mathilda these correspond to the \mcode{Gamma[2.5]}, \mcode{Gamma[2.5+1.3 I]},
and \mcode{N[Gamma[5/2], \sfapdps]} dispatch paths respectively. Arguments are drawn
deterministically from each head's real principal domain so that timing measures the
kernel, not a decline-to-fallback path. Arbitrary precision is sampled on the real axis.

\paragraph{Accuracy: agreement, not an oracle.}
No engine is designated the source of truth. For each sample point we collect the value
from every engine that returns a number, take the component-wise median as the consensus,
and report the number of leading significant digits the engines mutually share
($-\log_{10}$ of the largest pairwise relative spread). An engine whose value deviates
from the consensus by more than the regime tolerance --- while the others agree closely ---
is \emph{flagged}. Four independent implementations agreeing to $\approx 15$ digits in
machine precision (or to \sfapdps{} in AP) is strong evidence of correctness; a lone
dissenter is either a genuine branch/convention difference (documented) or a bug. This
agreement check doubled as the cross-engine mapping validator while the benchmark was
built.

\paragraph{Speed.}
Latency is timed \emph{inside} each engine (Mathilda/Mathematica \mcode{AbsoluteTiming},
Maxima \mcode{elapsed\_real\_time}, Python \mcode{perf\_counter}) so process start-up is
charged once, not per call. Each engine evaluates the head over a block of \emph{distinct}
arguments and we report the minimum per-call time over several such blocks: distinct
arguments mean no engine can serve a memoised result (Mathematica's \mcode{N} cache and
Mathilda's evaluation memo would otherwise measure the cache, not the arithmetic), and the
single pass per block avoids re-evaluating identical work. \mcode{AbsoluteTiming} is used
rather than \mcode{Timing}, which sums CPU time across threads.

Three further controls make the figure the \emph{kernel's} cost.
\begin{itemize}
\item \textbf{Machine literals.} Machine arguments are written with a trailing backtick
  (\mcode{1.2345678901234567`}). A 17-digit literal without the backtick is read as
  \emph{arbitrary} precision by both Mathilda and Mathematica, so the plain form would
  route part of the machine sample through the MPFR paths.
\item \textbf{Net latency.} Each block is timed twice: once calling the head, and once as
  a \emph{null loop} with the same \mcode{Do}/\mcode{Part} (Python: \mcode{for}) loop and
  no call. Neither loop is wrapped in \mcode{Quiet}. The reported latency is
  $\min_b(\text{raw}) - \min_b(\text{null})$ (512 points per block, 5 blocks).
\item \textbf{Cache defence.} \mcode{ClearSystemCache[]} is called before every timed
  loop. Values and timing run in separate engine processes. Python's warm-up uses its own
  points. A \emph{cache canary} then re-times block~0 on points it has already seen: a
  repeat more than $2\times$ faster than the first pass means the engine is serving
  memoised results. Such a cell is marked $^\dagger$ and excluded from the ranking.
\end{itemize} The vectorized-throughput
table instead gives each engine its best array form: a $10^6$-element packed buffer for
Mathilda and a NumPy array for SciPy (Maxima and Mathematica are scalar here and omitted).

\paragraph{Scope.}
All \sfncases{} numerically-evaluable heads are covered. The exact integer/rational heads
(\mcode{Fibonacci}, \mcode{LucasL}, \mcode{BernoulliB}, \mcode{EulerE},
\mcode{HarmonicNumber}, \mcode{BarnesG}, \mcode{Hyperfactorial}) are reported separately
as exact arithmetic. The two symbolic-only heads (\mcode{BesselJZero}, a Hadamard-product
placeholder, and \mcode{StieltjesGamma}, inert except at $0$) have no numeric path and are
excluded.

\section{Discussion}

\paragraph{Where Mathilda stands.} The medians over the sweep, as net latency against the
fastest other engine: machine real \sfspeedMR{}, complex \sfspeedC{}, arbitrary precision
\sfspeedAP{}. Mathilda has the lowest net latency in \emph{every} machine-real and
machine-complex cell, and its $10^6$-element buffers beat SciPy for every head SciPy
implements.

\paragraph{How the machine regimes were closed (v0.436--v0.444).} The first version of this
report (v0.433) had Mathilda a median $12\times$ slower for machine reals and $9\times$ for
complex arguments. Part of that was the measurement itself: 17-digit literals were read as
arbitrary precision, and the \mcode{Do}/\mcode{Part}/\mcode{Quiet} loop floor was charged to
every call. Both are fixed in the method above. The rest was real, and had three causes.
\begin{itemize}
\item \textbf{Scalar paths bypassed the machine kernels.} Most scalar builtins recomputed in
  MPFR, or rebuilt and re-evaluated an expression, even where an \mcode{sf\_machine}
  double kernel already existed. Every special-function builtin now goes first through one
  shared machine gate (\mcode{sf\_machine\_scalar\_args}) to the same raw-double kernel the
  packed, NDArray and \mcode{Compile[]} surfaces use, so the five surfaces agree bit for bit.
\item \textbf{No native complex kernels.} The \mcode{ncpx}-style MPFR pairs are replaced, for
  machine input, by raw double re/im kernels for every head:
  \begin{itemize}
  \item Faddeeva $w(z)$ for the error family and Fresnel
  \item Amos-style I/K reduction with Taylor continuation for Bessel and Airy
  \item Euler--Maclaurin and inversion maps for Zeta, HurwitzZeta, LerchPhi and PolyLog
  \item tiled Taylor/Stirling for $\ln\Gamma$ and $\psi$
  \item Carlson's integrals in complex arithmetic for the elliptic integrals
  \item transformation-selected series and ODE continuation for the hypergeometric family
  \end{itemize}
\item \textbf{Kernel algorithms.} Real kernels that lost to SciPy were rebuilt as fitted
  rational, Chebyshev and auxiliary-function approximations. Their coefficients are
  regenerated from mpmath by scripts under \mcode{tools/}.
\end{itemize}
Two evaluator costs were also cut. The confirming step after a builtin returns a numeric or
canonical-complex atom is gone, and so is the packed-array gate scan for calls with no
buffer argument. Accuracy rose with speed: the agreement table is at or above its v0.433
values, and every kernel was gated against mpmath (median $\lesssim 1$ ulp) before it was
wired.

\paragraph{DirichletL (v0.450).} Two rows cover the Dirichlet $L$-function: the real
character mod 5 (\mcode{DirichletL}, $k=5$, $j=3$) and the order-6 complex character mod 7
(\mcode{DirichletLc}, $k=7$, $j=2$), with $s$ sampled on $[-4,6]$ so that both sides of the
critical line are timed. SciPy and Maxima have no $L$-function; the Python column is
\mcode{mpmath.dirichlet}, given the character values in Mathematica's labelling. The machine
kernel runs Euler--Maclaurin on $L$ itself, with the integral terms summed as
$\mathrm{expm1}/\mathrm{log1p}$ so that nothing cancels as $s\to 1$, and the functional
equation for $\Re s<\tfrac12$. It is 180--200$\times$ faster than Mathematica at machine
precision, 145--160$\times$ on complex $s$, 10--12$\times$ at 50 digits (arb's
\mcode{acb\_dirichlet\_l} on the primitive character), and 160--175$\times$ on a $10^6$
buffer. The three flagged disagreements are not Mathilda's. Mathematica's own machine values
are wrong from the seventh digit in the left half-plane: at $(5,3,-3.3)$ it returns
$2.492235964$, where the 20-digit value is $2.4922356398\ldots$. The 50-digit
\mcode{DirichletLc} row is an mpmath artefact: a fresh mpmath process agrees with Mathilda
to 51 digits at all eight points, and Mathilda agrees with Mathematica at 50.

\paragraph{MeijerG (v0.445, v0.446).} Three rows cover the Meijer $G$-function: a two-term
$G^{2,1}_{2,3}$ (\mcode{MeijerG}), a $G^{2,2}_{2,2}$ whose Slater expansion switches from
$z$ to $1/z$ at the unit circle (\mcode{MeijerG22}), and the documented log case of
integer-spaced $b$'s (\mcode{MeijerGlog}). SciPy has no $G$-function and Maxima no numeric
one, so the Python column is mpmath's \mcode{meijerg} and Maxima is absent. Mathilda is the
fastest engine in all nine cells: against mpmath $32\times$, $128\times$ and $539\times$
(machine real), $42\times$, $245\times$, $469\times$ (complex) and $2.8\times$,
$2.1\times$, $5.1\times$ (50 digits), and Mathematica is slower still in every cell
($12$--$6500\times$). The machine path is one Slater plan per parameter set (the
$z$-independent $\pi/\sin$ and $\Gamma$ products) and one pFq kernel call per term; a
cancelling sum is handed to the arb engine. On a $10^6$-element buffer the plan is built
once for the whole buffer, not once per call, so the two non-log rows run at $1.0$ and
$0.23\,\mu$s per element. SciPy has no $G$-function, so these throughput rows have no
comparison column. The 50-digit
\mcode{MeijerG22} cell first came out level with mpmath ($2.03$ vs $2.07$\,ms) because
$N$ of the exactly reduced $_2F_1$ pair summed each series directly; routing
arbitrary-precision \mcode{Hypergeometric2F1} through arb's transformation-based kernel
fixed that, and took the \mcode{Hypergeometric2F1} AP cell from $0.62$ to $0.10$\,ms
($3.8\times$ ahead of mpmath).

\paragraph{The MeijerG log case (v0.446).} At v0.445 the log case had no machine form:
every point went to the arb engine, which perturbs the colliding $b$'s and compares two
perturbation sizes. That cost $456\,\mu$s per call and $119$\,s per $10^6$ buffer. It is
now summed on the machine path as the residue series of the Mellin--Barnes integrand,
$G=\sum_k w^{\beta+k}\sum_j c_{kj}\log^j w$, one series per integer-spaced class of $b$'s
with base $\beta$. The $c_{kj}$ do not depend on $z$, so the plan tabulates them once: a
Laurent expansion from arb, then the exact rational step $F(s+1)=F(s)R(s)$ in
double-double. A point is summed in double, re-summed in double-double when it
measurably loses more than 3 bits, and handed to arb only past 45. \mcode{MeijerGlog} now
costs $2.99\,\mu$s (real), $7.6\,\mu$s (complex) and $320$\,ms per $10^6$ buffer,
$85$--$370\times$ faster than v0.445. Its agreement figure (12.4 digits) is set by
Mathematica, whose machine log case is off by $3\times10^{-12}$ at $z=5.5$; Mathilda and
mpmath match 40-digit values to $\approx 10^{-16}$. The MeijerG rows were re-run at v0.446
and merged with the v0.445 hypergeometric run and the v0.444 run of the other heads
(\mcode{results/2026-10-17-final-v0446.json}).

\paragraph{Notes on the flagged disagreements.}
The recurring genuine differences are: Maxima's \mcode{expintegral\_chi} returns a value
with a spurious $i\pi$ imaginary part on the positive real axis (a branch convention);
Maxima leaves \mcode{hurwitz\_zeta}, \mcode{polylog}, \mcode{HypergeometricU},
\mcode{WhittakerM/W} and \mcode{BarnesG} symbolic (no numeric kernel, shown as absent, not
as a disagreement); and branch-cut choices for multivalued heads differ between systems
off the principal domain.

\section{Reproducing}

\begin{verbatim}
cd <mathilda-repo>
make -j                      # build ./Mathilda
benchmarks/.venv/bin/python benchmarks/97-special-functions/run_shootout.py --ap-dps 50
benchmarks/.venv/bin/python benchmarks/97-special-functions/report.py [results/<file>.json]
cd benchmarks/97-special-functions && latexmk -pdf special_function_performance.tex
\end{verbatim}

\noindent
The driver writes \mcode{results/<date>.json}; \mcode{report.py} regenerates every
\mcode{tab\_*.tex} fragment and \mcode{macros.tex} from it. Engine binaries are found via
\mcode{MATHILDA\_BIN}, \mcode{WOLFRAMSCRIPT}, \mcode{MAXIMA\_BIN}, and the benchmark venv.
