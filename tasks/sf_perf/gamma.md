# Special-function performance campaign — Gamma family (changelog prose)

Branch `sf-perf/gamma`. Heads: `Gamma`, `LogGamma`, `PolyGamma`, `Beta`, `Pochhammer`.

## Gamma family: one double kernel per head, shared by every machine surface

New `src/special_functions/sf_machine_gamma.{c,h}` holds the raw-double (re/im,
no `<complex.h>`) kernels: `sfg_digamma`, `sfg_polygamma`, `sfg_polygamma_c`,
`sfg_gamma_c`, `sfg_loggamma_c`, `sfg_beta(_c)`, `sfg_pochhammer(_c)`. Each is
the single implementation behind the scalar builtin, the packed / `NDArray`
element-wise kernels (`src/ndkernels.c`) and `Compile[]`, so scalar == List ==
packed == NDArray == Compile bit for bit (checked in `tests/test_gamma_machine.c`).
A kernel that declines (pole, out of regime, overflow) falls through to the
existing exact / MPFR path unchanged. `sf_machine_digamma`, `sf_machine_polygamma`
and `sf_machine_pochhammer` in `sf_machine.c` now delegate to these kernels, so
`HarmonicNumber` and the hypergeometric digamma sums share them.

What changed per head:

- **PolyGamma.** The machine scalar path computed in MPFR (`mpfr_digamma` / an
  MPFR-pair asymptotic) and rounded, and the one-argument form rebuilt
  `PolyGamma[0, z]` and re-evaluated it. Now a machine real or complex `z`
  with integer order 0 ≤ n ≤ 40 goes straight to the kernel, ahead of every
  exact / symbolic ladder; `PolyGamma[z]` computes directly for machine `z`
  (symbolic `z` still canonicalises to `PolyGamma[0, z]`). Complex `PolyGamma`
  now has packed / NDArray / Compile kernels (it had none: complex arrays
  declined to the List path).
  - ψ real: degree-22 Chebyshev interpolant of ψ(x)/(x − x₀) on [1, 2] times
    (x − x₀), x₀ = 1.4616… as a double-double (relatively accurate through the
    zero; Cody–Strecok–Thacher 1973 technique); exact integer shifts to [1, 2]
    from (0, 10); asymptotic series beyond; reflection with an exactly reduced
    cotangent for x < 0.
  - ψ⁽ⁿ⁾ real, n ≥ 1: upward recurrence + Hurwitz-zeta asymptotic tail
    (DLMF 25.11.43), with first-order corrections for the rounding of each
    x + j and a compensated (Neumaier) sum.
  - Complex: Taylor tiles (below) for ψ, a Taylor series about x₀ for
    |z − x₀| ≤ 0.35, recurrence + asymptotic series elsewhere, reflection
    (DLMF 5.5.4) for Re z < −5; ψ⁽ⁿ⁾ (n ≥ 1) by the recurrence + tail for
    Re z ≥ 0.
- **Gamma / LogGamma, complex.** The Lanczos (g = 7, n = 9) series through
  `<complex.h>` (`cpow`/`clog`/`__divdc3`) is replaced, and the scalar path now
  tests for machine complex before the exact / symbolic ladders.
  - Taylor tiles: for −5 ≤ Re z < 10, |Im z| < 19/4 the exact recurrence moves
    z into the strip 1 ≤ Re < 5/2 and a Taylor series about the nearest of 30
    centres {1.25, 1.75, 2.25} + {0, ½, …, 9/2} i is summed (16–36 terms, by
    Estrin's split into four interleaved Horner chains). Both real zeros of
    lnΓ (z = 1, 2) and ψ's (x₀) lie inside the strip, so no recurrence step
    cancels to reach them; on the real row the series is for
    lnΓ/((z−1)(z−2)), carrying both zeros exactly. (Shifting to Stirling
    instead forms lnΓ as a difference of O(10) numbers — the old path's error
    was up to 689 ulp next to z = 2.)
  - Elsewhere: Stirling's series after shifting Re z ≥ 7. The N logs of the
    shift are one log of the product, with the 2πi windings counted as the
    running product crosses the negative real axis — exactly the continuous
    branch (Hare 1997) Mathematica uses.
  - Gamma = exp(E)·P^(±1) with ONE complex exponential, and E carried as a
    double-double (the tile constant term; Dekker products and an
    extra-precise log|w| — frexp + log1p — in Stirling), because exp turns E's
    absolute error into Gamma's relative error. Median error over
    −10..30 × ±20i fell from 66 ulp (old Lanczos) to 3.6 ulp.
  - Re z < −30 and overflow fall back to the old Lanczos/reflection path.
- **Beta.** Machine real or complex is computed directly in double (no
  `Gamma[a] Gamma[b] / Gamma[a+b]` expression rebuild). Real:
  `tgamma(a)/tgamma(a+b)·tgamma(b)` with the rounding of a + b undone through
  ψ (`Γ(s+e) ≈ Γ(s)(1 + ψ(s)e)`; uncorrected it cost up to 18 ulp). Complex:
  the three Gammas under one exponential (double-double exponents summed),
  the same ψ correction. Complex Beta now has an ND / Compile kernel.
- **Pochhammer.** Machine real or complex is computed directly in double (no
  `Times[a, a+1, …]` / Gamma-ratio rebuild): integer n (|n| ≤ 256) as the
  product (or reciprocal product for n < 0), otherwise the corrected Gamma
  ratio. `Pochhammer[a, 0]` keeps its exact 1. Complex Pochhammer now has an
  ND / Compile kernel.

Coefficient tables are generated by `tools/sf_accuracy/gen_gamma_tables.py`
(mpmath, 60–120 digits); `tools/sf_accuracy/gamma.py` is the accuracy gate
(≥ 2000 points per head per regime against mpmath at 30 digits).

columns there read ~10–20 % above the baseline's Python figures).

The shootout's agreement digits rose in every one of the twelve cells (e.g.
Beta C 14.0 → 16.0, LogGamma MR 14.4 → 15.5, Gamma C 14.5 → 14.7).
PolyGamma previously went through MPFR and was correctly rounded; it is now
≤ 3.5 ulp real (median ≈ 0.5), the price of a ~100–200× faster call.
