# Changelog: week of 2026-10-19 (Mon) – 2026-10-25 (Sun)

## Mixed exact and inexact arguments numericalize; the special-function numeric gaps closed ; v0.477

`Zeta[2., Sqrt[2]]` is now a number, as `Sin[2.]` is, and so is every special function given an inexact argument beside an exact irrational one. A sweep of 279 calls over every special function — all-machine, and with each argument in turn left as an exact irrational constant — was run against the reference. With the evaluator rule below already in, 42 calls still disagreed, all in heads that had no numeric path for those arguments at all. After the fixes below, two disagree, and they are a deliberate difference (`HarmonicNumber`, below). The new tests are in `tests/test_mixed_numericalize.c`; every expectation was verified against the reference.

### The evaluator rule

- When a `NumericFunction` builtin declines a call whose arguments are numbers, numeric quantities or Lists of them, with at least one inexact and at least one irrational exact argument, the evaluator calls it once more with the irrational arguments numericalized to the lowest precision among the inexact ones (machine precision being the floor). `numeric_mixed_args_call` (`src/numeric.c`) does this, and it is step 5a of `evaluate_step`.
- Integers and rationals are not converted, since they are often an index (`BesselJ[2, …]`, `ProductLog[1, …]`). `NHoldFirst` / `NHoldRest` positions are skipped. `Flat` heads keep their own contagion pass.
- A decline that emitted a message is not retried. A symbolic argument or a user-defined `NumericFunction` head leaves the call unevaluated, as in the reference.
- The rule fixed, among others:
  - `Zeta`, `BesselJ`/`Y`/`I`/`K`, `Gamma`, `Beta`, `PolyLog`, `Hypergeometric0F1`/`1F1`/`2F1`/`PFQ`/`U`, `ArcTan`, `Log[b, x]` and `Binomial`;
  - `Pochhammer`, `EllipticE`/`F`/`Pi`, `ExpIntegralE`, `HurwitzZeta`, `LerchPhi`, `Whittaker*`, `StruveH` and `MeijerG`;
  - the orthogonal polynomials.
- `Zeta[2.`30, Sqrt[2]]` gives 30 digits.
- Deliberate difference: `HarmonicNumber[Pi/3, 1.36]` evaluates. The reference evaluates the all-machine call but leaves the mixed one unevaluated.

### Heads that had no numeric path

- **`Surd` (new).** The real n-th root. Exact (`Surd[-8, 3] = -2`, `Surd[Sqrt[2], 3] = 2^(1/6)`), machine (`sf_surd_r`, shared by packed, `NDArray` and `Compile`) and MPFR.
  - Messages: `::noneg`, `::indet`, `::preal`, `::int`, `::argr` and `::argrx`.
  - An integer-valued real `n` is accepted (documented difference).
- **`KroneckerDelta` (new).** `NumericFunction` and `Orderless`. Identical arguments give 1, numeric arguments compare by `Equal`, and one unequal pair gives 0.
- **`Max` / `Min`** order real numeric quantities with the numbers and keep the winner exact: `Max[1, Pi] = Pi`, `Max[1., Pi] = Pi`. These stayed unevaluated before.
- **`HeavisideTheta` / `DiracDelta` with several arguments** (`src/internal/distributions.m`). A product: 0 or 1 by the signs. Positive arguments are dropped.
- **`StieltjesGamma`.**
  - `StieltjesGamma[n, a]` with an inexact `a` evaluates through arb.
  - `N[StieltjesGamma[3]]` evaluates. It used to give `StieltjesGamma[3.]`; the attributes now include `NHoldFirst`, which `N` honours.
  - `a ≤ 0` integer gives `ComplexInfinity`.
  - `StieltjesGamma::intnm` for a bad order.
- **`ExpIntegralE`** of any real, complex or arbitrary-precision order goes through arb's `acb_hypgeom_expint`. Before, only integer orders at machine precision evaluated. `E_s(0.)` for `s ≤ 1` is `ComplexInfinity`.
- **`PolyGamma` of non-integer order**, in the reference's Riemann–Liouville convention:
  - It was fitted to the reference's values and then confirmed to about 22 digits; arb's own generalisation differs.
  - It is a new arb kernel, `flint_num_polygamma_frac`.
  - Integer orders that the ladder declined now also fall to arb.
- **`LegendreP` / `LegendreQ` of general degree and order** use arb's `acb_hypgeom_legendre_p/q`.
  - Types 1 and 2 map to arb type 0; type 3 maps to arb type 1.
  - Checked inside and outside (-1, 1) and at complex `x`.
  - `N` of the four-argument form works; the type label `2.` is accepted.
- **`FactorialPower[x, n, h]`**, the step form, was never implemented.
  - It covers a positive integer, a negative integer or a non-integer `n` for numeric `x` and `h`.
  - `FactorialPower[5, -2] = 1/42` now evaluates.
- **`QPochhammer`.**
  - A non-integer `n` is `(a; q)_∞ / (a qⁿ; q)_∞`. A negative integer `n` is exact.
  - A complex or MPFR infinite product evaluates through arb; it used to be rounded to a double.
  - The machine path uses the shared kernel.
  - At (`Sqrt[2]/3`, 0.866, `Pi/3`) the reference is off by 1.3×10⁻¹⁴, confirmed with mpmath.
- **`BesselJZero`** was a placeholder that never evaluated.
  - It now evaluates for a real order `n > -1` with an inexact argument or under `N`.
  - Machine values use McMahon's expansion or a sign-change scan, then Newton (`sf_bessel_j_zero_r`, shared by packed, `NDArray` and `Compile`), and are within 3 ulp.
  - Arbitrary precision uses Newton in arb.
- **Nielsen `PolyLog[n, p, z]`** was always symbolic.
  - `p = 1` reduces to `PolyLog[n + 1, z]`.
  - For a positive integer `p` and |z| < 1 the Stirling-number series is summed in arb.
  - Still unevaluated (the reference evaluates both): |z| ≥ 1 and a non-integer `p`.

### Related fixes found on the way

- `Equal` / `Less` of two exact rationals with big parts compare exactly: `1 == 1 + 10^-20` was `True`.
- `N` honours `NHoldFirst` / `NHoldRest` in general, not only for `DirichletL`'s labels.
- `builtin_arg_error` uses the reference's `argr` (one argument against a fixed count above one) and `argtu` (one argument against "m or n") tags.

### Documentation

- The spec (`docs/spec/`, `Mathilda_spec.md`) no longer names the reference system. It says "the reference", defined once in `Mathilda_spec.md`.
- The ```` ```mathematica ```` code-fence tag is kept: the docs-site tooling (`site/`, `frontend/`, `tools/gen_image_examples.py`) keys on it.
- `docs/spec/builtins/calculus.md` is untouched; it has uncommitted edits.

## Number-theory review, batch 7: Zeta, LerchPhi, DirichletL, Log2, LogIntegral, AlgebraicNumberNorm ; v0.476

The last batch of the review of the 38 implemented number-theoretic functions. Expectations were verified against the reference; machine values were checked against 40-digit values. The new tests are in `tests/test_analytic_review.c`.

### Zeta

- **`IncludeSingularTerm`**, the option the reference has and Mathilda lacked: `Options[Zeta] = {IncludeSingularTerm -> False}`, and with `True` an integer `a ≤ 0` gives `ComplexInfinity` for `Re s > 0` (exact or inexact). The options are validated by a new shared reader, `options_parse_bools` (`src/options.c`): `Zeta::optx`, `::opttf`, and `::nonopt` for a third positional argument, which was `::argt`.
- **Exact `Zeta[s, a]` at `a ≤ 0`**, previously unevaluated: shifted into (0, 1] with the finite head as one GMP rational, on the reference's rules (`Zeta[2, -1] = 1 + Pi^2/6`, `Zeta[2, -3/2] = 40/9 + Pi^2/2`, `Zeta[0, -1] = 3/2`, `Zeta[x, -1] = 1 + Zeta[x]`). The same rules now also apply to `a > 1`: `Zeta[x, 3]` and `Zeta[3, 4]` stay folded, as in the reference, where they used to expand, and `Zeta[3, 5/2] = -224/27 + 7 Zeta[3]` is new. `Zeta[0, a] = 1/2 - a`.
- **Machine `Zeta[s, a]` at a real `a ≤ 0`** has a kernel, `sf_zeta2_r/_c`, shared by the scalar path, a new binary `NDArray` kernel and `Compile`. `Zeta[2.5, -1.5 - k/10⁴]` costs 1.1 µs, from 0.34 ms through MPFR, against 13 µs for the reference. Machine values at `a ≤ 0` are within 1.6 ulp. Machine `s = 0` now counts the 0⁰ term, so `Zeta[0., -1] = 1.5` (it was 0.5). `Zeta[2.5, NDArray[…]]` used to stay unevaluated, and `Zeta[s, a]` did not compile at all.
- **Exact even `s`**: Bernoulli numbers come from FLINT, and the finished value is memoised. Cold `Zeta[400]` takes 0.5 ms, from 31 ms (the reference takes 11 ms); 200 warm calls take 2.4 ms, from 11.8 ms.

### LerchPhi

- **The branch cut z > 1** evaluates. It used to stay symbolic. The value is the limit from below, the `PolyLog` convention: `LerchPhi[2., 2., 1.] = Pi^2/8 - I Pi Log[2]/2`. Results are within 0.46 ulp, where the reference is off by up to 2130 ulp. **`DoublyInfinite -> True`** with |z| < 1 therefore evaluates too. Cost is about 1.1 ms a call, roughly 3× the reference; arb's own |z| > 1 algorithm floor is about 0.75 ms.
- **Options are validated and registered**, `Options[LerchPhi] = {DoublyInfinite -> False, IncludeSingularTerm -> False}`, with `::optx`, `::opttf` and `::nonopt`. An unknown option used to be `::nonopt`, and a non-Boolean value was accepted silently.
- **The machine kernel takes `a ≤ 0`**, by the same shift as `Zeta`, and treats `z = 1.` as `Zeta[s, a]`. `LerchPhi[1., 2., -1.5]` used to stay unevaluated.

### DirichletL, Log2, LogIntegral, AlgebraicNumberNorm

- `DirichletL`: attributes are now `{Listable, NHoldAll, Protected}`, as in the reference (it had `NumericFunction`). `NumericQ[DirichletL[4, 2, 3]]` is `False`, and `1. + DirichletL[4, 2, 3]` stays unevaluated; `N` still evaluates it.
- `Log2` / `Log10`: exact powers are found by a bit scan (`Log2[2^k]` for k ≤ 10⁴: 2.37 s → 6.5 ms; the reference takes 0.11 s). `Infinity` and `ComplexInfinity` give `Infinity`, and `Indeterminate` gives `Indeterminate`; they were left as `Infinity/Log[2]`. `Log[ComplexInfinity] = Infinity` and `Log[Indeterminate] = Indeterminate`. Packed real arrays use the real arm first. `ndarray_map_unary` tries an escaping kernel's `real` arm over a float64 buffer before going complex, with bit-identical results: packed `Log2` takes 3.4 ms → 1.4 ms for 10⁶ elements (the reference takes 1.2 ms).
- `LogIntegral`: li(0.) = 0 on every surface; it was `Indeterminate`. `LogIntegral[ComplexInfinity]` stays unevaluated; it was `Indeterminate`.
- `AlgebraicNumberNorm`: `::argx` for no argument, `::nonopt` for a second positional argument and `::optx` for an unknown option; these used to be silent. An element outside the extension is `ToNumberField::nnfel`, as in the reference; it was `AlgebraicNumberNorm::ext`. The first `Extension` setting wins.
- Docstrings for all six were rewritten.

### Recorded, not changed

- Mixed exact-irrational and inexact arguments (`Zeta[2., Sqrt[2]]`, `LerchPhi[Exp[I], 2., 1.5]`) stay unevaluated, as for every special function here. (Fixed in v0.477, above.)
- Big-float precision tracking does not use the condition number (`Log2[3.`30]`).
- `Infinity Pi` does not fold to `Infinity`.

These are global and outside this review. Compiled `LerchPhi` remains scalar-only, like every N-ary kernel. Exact `DoublyInfinite` closed forms evaluate where the reference stays unevaluated.

## Parser and matcher: `sym:patt` precedence (issue #102), and an exhaustive reference-graded matcher corpus ; v0.475

**Issue #102.** `MatchQ[f[1, 2, g[]], f[__, n_*a:_g]]` returned `True` and
`MatchQ[f[1, g[]], f[_, n_.*a:_g]]` returned `False`; the reference gives the opposite. The
cause was the **parser**. `:` was an ordinary low-precedence infix operator, so
`n_.*a:_g` parsed as `Optional[n_.*a, _g]`, a different and silently wrong
pattern. In the reference, `:` takes its left operand at **atom level**: the bare symbol
(`Pattern`) or blank token (`Optional`) right before it. `parse_colon_suffix`
(`src/parse.c`) now attaches `:` in `parse_primary`. A `colon_hold` marker stops
an inner token from claiming the `:` that ends a `sym:p` operand (`a:b:c` is
`Optional[a:b, c]`). This was checked against 100 forms from the reference and
all agree, except two that the reference rejects and Mathilda still accepts leniently. The
forms include `n x_:0` → `Times[n, x_:0]`, `x + a:_g == b` →
`Plus[x, a:(_g == b)]`, `x?f:_`, `x|a:b` and `x:a:b:c:d:e`. A parse of all 646
tracked `.m`/`.wl` files with the old and new binaries found no change in real
code.

**Exhaustive corpus.** `tools/gen_match_exhaustive_corpus.py` crosses 18
construct families with shared subject sets. The families are Blank and head
patterns, sequences, nonlinear names, `sym:p` with every operator, Optional and
defaults, Alternatives, PatternTest/Condition, Repeated, Except/HoldPattern/
Verbatim, (Orderless)PatternSequence, Longest/Shortest, literal number
structure, KeyValuePattern, Orderless/Flat/OneIdentity heads, query heads at
level specs, definitions, and parse shapes. A named pattern is asked through
`ReplaceList`, which pins bindings, backtracking order and completeness, not just
yes/no. **Every expected value comes from a reference kernel**, with each
case in a fresh context. That gives 11,385 gating cases
(`tests/match_exhaustive_corpus.m`, ctest `match_exhaustive_corpus_tests`, about
35 s). Another 413 known divergences are annotated report-only cases in
`tests/match_exhaustive_observe.m`. An ordering-only divergence keeps a gating
multiset twin (`Sort[ReplaceList[…]] === Sort[{…}]`). The runner's parent no
longer polls on a fixed 20 ms sleep, which had put a 20 ms floor under every
case (at least 6 s for the old 300-case corpus, which now runs in 1.4 s).

**Matcher bugs the corpus found, all fixed and checked against the reference:**
- **Alternatives:** a name in a branch that was not taken is bound to
  `Sequence[]` once the whole match succeeds (`1 /. (x_ | y_) :> {x, y}` is
  `{1}`). A later occurrence can still bind it.
- **`sym:p` backtracking:** the name is bound first and `p` is matched with the
  real continuation. Before, `ReplaceList[2 x, p:x_.*y_ :> …]` found one of
  three matches.
- **OneIdentity** applies only through Optional/defaults, as in the reference. Before,
  `h[x_]` matched `x`, `h[a, b]` (as `x -> h[a, b]`) and, under Flat, `h[]`, and
  `h[a]` matched twice. A Flat head no longer repeats its default match
  (`x_. + y_` against `a + x`).
- **Orderless:** a literal element takes only the first equal argument
  (`ReplaceList[o[a, a], o[a, x_] :> x]` is `{a}`).
- **OrderlessPatternSequence** matches a contiguous run at its own position, in
  any order, and its elements may be sequence patterns. Before, it matched any
  subset anywhere: `f[1, 2, 3]` matched `f[3, OrderlessPatternSequence[1, 2]]`.
  Four hand-written corpus rows had encoded that and were corrected.
- **`x__..`** and other variable-width repeats backtrack into their unit split
  through a continuation (`ReplaceList[f[a, a], f[x__..] :> {x}]` is
  `{{a}, {a, a}}`). The sequence commit step is shared (`seq_commit`).
- **Level specs:** a mixed spec like `{2, -1}` matched nothing in `Cases`,
  `Count`, `Position`, `DeleteCases` and `MemberQ`. One `in_level_spec` helper
  replaces five copies, and it walks `Depth` only when a bound is negative.
- **Redefinition:** an alpha-equivalent left-hand side replaces the rule
  (`f[x_] := x^2; f[y_] := y^3` is one rule). Each rule stores an alpha-invariant
  hash, so 3,000 distinct definitions cost the same as before.
- **Dispatch arity:** `PatternSequence`, `OrderlessPatternSequence`,
  `Longest`/`Shortest` and sequence-branch `Alternatives` arguments make a
  DownValue variable-arity. `q[PatternSequence[a_, b_], c_]` never fired before.
- **`OptionsPattern[{o -> v}]`:** inline defaults are used by `OptionValue`.
- The hand-written corpus row `1 /. (x_ | y_) :> {x, y}` → `{1, y}` had been
  written from memory and was wrong; it now expects `{1}`.

**Known, recorded, not fixed here.** The reference's `ReplaceList` enumeration under Flat
without OneIdentity wraps one-operand slices both ways and repeats matches.
Orderless enumeration *order* with Optional elements follows the reference's canonical
order, which sorts patterns after other expressions; Mathilda's `expr_compare`
does not (`Sort[{{2, x}, {1, 2 x}}]` also differs). SubValues
(`f[x_][y_] := …`) are not implemented. `SequenceCases` and `SequencePosition`
are missing.

## Documentation site: formulae blank after in-site navigation

Most formulae on the docs site rendered blank when a page was reached by
clicking a link (Material's `navigation.instant`), though a direct load or
refresh was fine. Instant navigation leaves MathJax's CHTML stylesheet
detached, and MathJax's default "adaptive" CSS adds one rule per glyph via
CSSOM `insertRule` — which then fails (`sheet` is null), so every glyph the
first page had not used came out invisible. `site/docs/javascripts/mathjax.js`
now sets `chtml.adaptiveCSS: false` (all glyph CSS is static text, which
survives detaching) and re-attaches the stylesheet before re-typesetting.
MathJax is pinned to `3.2.2` and loads the TeX-only `tex-chtml` bundle: the
`tex-mml-chtml` bundle's MathML input re-typeset MathJax's own hidden assistive
`<math>` copies on every page, doubling each formula for screen readers.
Verified in headless Chrome over a five-page instant-navigation chain and a
direct load.

Fifteen tutorial headings that held inline TeX (e.g. `### 4.7 "Lattice": a miss
of \(2^{28}\)`) showed the raw TeX in the right-hand table of contents, which
MathJax never typesets. They now use Unicode and Markdown emphasis (`2²⁸`,
`*B*₁`, `*y*² = *x*³ + *k*`); their anchor slugs are unchanged.

## Number-theory review, batch 6: partitions ; v0.474

This applies the DivisorSigma review to `IntegerPartitions`, `PartitionsP` and `PartitionsQ`. Expectations were verified against the reference; the new tests are in `tests/test_partitions_review.c`.

### IntegerPartitions

**Semantics fixed**:
- **A negative length step** (`{6, 2, -2}`: lengths 6, 4, 2) was read as step 1.
- **A number as the part spec** (`IntegerPartitions[6, All, 2]`, parts `Range[2]`) was unevaluated.
- **`m`** accepts `None` and Take sequences (`{3}`, `{2, 4}`, `{1, -1, 3}`). A sequence past either end clamps with `::take` (`{2, 30}` of 11 rows is rows 2–11).
- **A bignum `n`** with a length bound or a positive `m` (`IntegerPartitions[10^20, {3}, All, 2]`) gave `{}`, because the default part list could not be built.
- **The four argument messages** (`rat`, `nninfseq`, `rseq`, `seq`) were missing. A bad argument used to stay unevaluated silently, or answer: `{1, 2, 0}` was taken as step 1, and a negative `k` gave `{}`.

**Engines.** The old enumerator did exact rational arithmetic at every step and walked all n default parts for every row. Three machine-integer engines replace it wherever the inputs allow, producing the same order:
- a range-mode walk with no part list, which also serves `IntegerPartitions[10^7, {2}]`;
- an ascending-list walk;
- an int64 count-vector walk for unsorted or repeated lists.

The results match the reference on 11,083 grid cases over n, length spec, part spec and m, and on 4,800 unsorted and repeated part-list cases.

| workload | before | after | reference |
|---|---|---|---|
| `Length[IntegerPartitions[50]]` | 2.0 s | 0.072 s | 0.053 s |
| `Length[IntegerPartitions[60]]` | 10.7 s | 0.36 s | 0.27 s |
| `IntegerPartitions[100, {4}]` | 1.33 s | 0.0011 s | 0.0011 s |
| `IntegerPartitions[60, All, {11, 7, 5, 3, 2, 1}]` | 0.128 s | 0.0031 s | 0.0022 s |
| `IntegerPartitions[300, {5}, Prime[Range[30]]]` | 0.99 s | 0.00024 s | 0.0015 s |

The rest of the remaining 1.35× is allocation: one `List` node and one argument array per row.

**Evaluator.** A new `eval_stamp_list_literal` (`src/eval.c`) stamps a freshly built List-of-literals result as a GROUND fixed point. The evaluator no longer re-walks 3.6·10⁶ nodes after `IntegerPartitions[50]` returns. It stamps nothing when `List` carries rules.

**Memory bug.** The call string in the `undef`/`take` messages was built one byte short of its terminator, so a call whose text landed exactly on the buffer boundary overran the heap. That happened only after thousands of message-path calls, and it predates this review.

### PartitionsP and PartitionsQ

- **Small n**: `p(n)` and `q(n)` for `n < 1000` come from tables filled once at startup (under a millisecond). Before, every call reran the O(n^1.5) recurrence:

  | workload | before | after | reference |
  |---|---|---|---|
  | `Do[PartitionsP[i], {i, 300}]` | 7.0 ms | 0.05 ms | 0.38 ms |
  | `Do[PartitionsQ[i], {i, 1000}]` | 147 ms | 0.49 ms | 5.3 ms |

- **The q series** (Hagis) used to evaluate every character sum at full precision, with GMP-rational Dedekind sums. The fix:
  - `6k·s(h,k)` is an integer, so each Dedekind sum is computed by reciprocity in double and rounded, with an exact fallback.
  - Each angle becomes the exact rational `πR/(6k)`.
  - Each term is evaluated at its own magnitude, most of them in double.

  | workload | before | after | reference |
  |---|---|---|---|
  | `PartitionsQ[10^4]` | 0.125 s | 0.0027 s | 0.034 s |
  | `PartitionsQ[10^5]` | 1.72 s | 0.024 s | 0.73 s |

  `partitionsq_tests` (an exhaustive series-against-recurrence check) went from 83 s to 4 s.
- **Machine surfaces**: the int64 prefix of the tables is one shared helper (`partitions_p_i64` / `partitions_q_i64`). It backs the scalar builtins, new packed/NDArray kernels (on `AWARE` and `INT64_OK`), and new `Compile` opcodes `OP_PARTP_I` / `OP_PARTQ_I`, which bail past `p(405)` / `q(769)`. Scalar, List, packed, NDArray and Compile agree bit for bit. A packed `PartitionsP` over 10⁶ elements takes 12 ms.
- **Docstrings**: the three docstrings are rewritten.

## Number-theory review, batches 4–5: factorisation, divisors and digits ; v0.473

This applies the DivisorSigma review to `FactorInteger`, `Divisors`, `SquareFreeQ`, `IntegerDigits`, `FromDigits`, `DigitCount` and `IntegerExponent`. Every expectation was checked against the reference. The new tests are in `tests/test_factor_digits_review.c`.

### Wrong answers fixed

| call | Reference        | before |
|---|---|---|
| `FactorInteger[360, 2]` | `{{5, 1}, {72, 1}}` | `{{2, 3}, {45, 1}}` (wrong grouping) |
| `FactorInteger[100, 2]` | `{{2, 2}, {5, 2}}` | `{{2, 2}, {25, 1}}`; the spec claimed this without checking it |
| `FromDigits[{{1, 2}, -1}]` | `3/250` | `{9, 19}` |
| `FromDigits[{{1, 2}, {3, 4}}]` | `{120, 1200}` | `{13, 24}` |
| `FromDigits[{1, 2, 3}, -10]` | `83` | unevaluated |
| `FromDigits["MCMXC", "Roman"]` | `1990` | unevaluated |
| `DigitCount[0]` | `{0, …, 0, 1}` | all zeros |
| `DigitCount[2.5, 2]` | `{2, 51}` | unevaluated, with `::int` |
| `DigitCount[{1, 2, 3}]` | one count list per element | unevaluated |
| `SquareFreeQ[(x - 1)^2, Modulus -> 2]` | `False` | `modnotimpl` |
| `SquareFreeQ[{12, 30}]` | unevaluated | `False` |

- **`FactorInteger[n, k]`** now follows the reference's grouping (`fi_builtin.c`, `partial_result`):
  - trial division to 2^16 first;
  - the largest prime powers are kept and the smallest merged;
  - an unfactored cofactor is split smallest-first into the room left;
  - The reference's sign placement;
  - entries sorted by base.
  
  It matches the reference on a 185-case table. The cofactor split can differ when only some of three or more cofactor primes fit, because the reference's split follows its own search order. `All`/`Infinity` are accepted as `k`, and `argt`/`nonopt` are emitted.
- **`SquareFreeQ` with `Modulus -> p`** tests univariate polynomials over GF(p), using `PolynomialGCD[f, f', Modulus -> p]`. Bad options and `Modulus` on a number emit the reference's `SquareFreeQ::par`.
- **`Divisors`** emits `argx`, `nonopt`, `optx` and `opttf`, as the reference does, through the shared Gaussian option parser.
- **`FromDigits`**:
  - the `{digits, exponent}` mantissa form, with recurring blocks;
  - Roman numerals, with `FromRomanNumeral::nrom`;
  - any integer base for lists;
  - the Horner form for symbolic digits (`c + 10 (b + 10 a)`);
  - `argt`.
- **`DigitCount`**:
  - threads over a list in its first argument (it is still not `Listable`);
  - counts the `RealDigits` of a real;
  - `{d1, d2, …}` digit lists;
  - The reference's `digp` text.
- **`IntegerDigits`** emits `ibase` and `intnm`, and **`IntegerExponent`** emits `ibase`.

### Performance

| workload | before | after | Reference        |
|---|---|---|---|
| `IntegerDigits[3^200000]` | 0.78 s | 0.0035 s | 0.0038 s |
| `IntegerDigits[Range[10^6]]` (packed) | 1.23 s | 0.36 s | 0.47 s |
| `IntegerExponent[Range[10^6], 2]` (packed) | 0.45 s | 0.021 s | 0.087 s |
| `FromDigits` of 10^5 packed digits | 0.27 s | 0.0018 s | 0.0015 s |

- **Bignum digits** go through GMP's subquadratic `mpz_get_str`/`mpz_set_str`, and both ends stay on buffers:

### Prime counting: a tuned Deleglise–Rivat

- **Tuning**: $y = \alpha x^{1/3}$ with $\alpha = 0.0008\ln^3 x$.

- **Easy leaves** come from the π table, and above √z only prime $m$ are walked.

- The operand binds tighter than binary `+` and looser than `*`/`^`:
  `+a b` is `Plus[Times[a, b]]`, `+a^2` is `Plus[Power[a, 2]]`, and
  `+x == y` is `Equal[Plus[x], y]`.
- A signed literal is unchanged (`+5` is the integer `5`), as is `++x`
  (`PreIncrement`).

## Correctness/performance: the v0.464 limitations closed; Reduce transcendental roots; InputForm round-trip ; v0.465

- **Reduce over the reals with transcendental breakpoints.** `Reduce` now solves univariate exp-trig-polynomial inequalities and equations whose roots `Solve` cannot find. It isolates the real roots with certified arb interval arithmetic on a provably bounded region and returns them as exact rationals or as transcendental `Root[{f, x0}]` objects. `Reduce[Sin[x] > x/2, x, Reals]` gives `x < Root[{#1 - 2 Sin[#1] &, -1.89549}] || 0 < x < Root[{#1 - 2 Sin[#1] &, 1.89549}]`, as the reference does. Infinitely many roots (`Sin[x] > 0`) or no provable bound still leaves Reduce unevaluated. `Root[{f, x0}]` is certified by interval Newton, refines to any precision under `N`, canonicalises x0 and its body, and gives `Root::invrt` for an x0 that is not at a root. A six-digit printed x0 reads back.
- **Reduce input normalisation.** `Not[a > b]` folds to `a <= b`, with De Morgan through `And` and `Or`, and over Reals a relation side carrying `Re`/`Im`/`Conjugate` is ComplexExpanded. A residual that vanishes on a whole interval (`ArcCos[1 - 2 x^2] - 2 ArcSin[x]` on [0, 1]) is decided cell by cell instead of burning the isolation budget. This restores `Refine[Cos[x] > 0, -Pi/2 < x < Pi/2] = True`, `Simplify[ArcCos[1 - 2 x^2] - 2 ArcSin[x], 0 < x < 1/2] = 0` and `Simplify[Sqrt[E^(2 I x)] - E^(I x), -Pi/2 < x < Pi/2] = 0`. All three had regressed in v0.464, which had removed the unsound one-sample shortcut that had decided them by luck.
- **Rules on ordered Flat heads are cheap again.** A failing rule on `**`, `Dot`, `And`, `Or` or a user `Flat` head paid a full match at every start offset after v0.462: seconds at n = 100 for `ff[x_, y_, x_]`, and n³ for `And[x_, Not[x_]]`. Offsets and spans that cannot match are now skipped using the pattern's first single-operand element as an anchor, and a group that cannot equal an already-bound name is rejected without being built. Repeated-name and anchored rules now cost about what v0.461 did. `PatternSequence[...]` elements now also match interior runs.
- **FactorInteger: bignum Fermat and Lehman.** The Fermat residue filter tests 64 candidates per block with precomputed bit masks: 0.5 ns per value instead of 10 ns. The Lehman sweep gives k = 1 about 5/6 of each round, and a larger "Iterations" never finds less. Near-square factors are cheap again (NextPrime[10^25]·NextPrime[10^25+10^16] takes 2.5 ms, against 77 ms in v0.464), and ratio-3, 5/7 and 2/3 factors stay at a few ms. The default Lehman budget is now 2^28.
- **InputForm round-trips machine reals.** `InputForm`/`FullForm` and `ToString[_, InputForm]` print a machine real as the shortest decimal that reads back to the same double (6 digits before), with the machine mark `` ` `` on a 17-digit mantissa and `*^` exponents. A machine `*^` literal now parses with one correct rounding (`1.5*^-5` was one ulp off).
