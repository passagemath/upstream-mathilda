# Changelog: week of 2026-10-19 (Mon) – 2026-10-25 (Sun)

## Definite integrals are reduced to named functions ; v0.504

Definite results that contain MeijerG or `PolyLog` at roots of unity now go through those
reductions. A rewrite is kept only when it removes every MeijerG/pFq, or is strictly
smaller without adding PolyGamma.

| Integral | Result |
|---|---|
| `∫₀^∞ x J₀(ax)/(x²+c²) dx` | `BesselK[0, a c]` |
| `∫₀^∞ J₀(ax) Sin[bx]/x dx`, `b > a > 0` | `Pi/2` |
| `∫₀¹ ArcTan[x]/x dx` | `Catalan` |
| `∫₀^{π/2} x Log[2 Cos x] dx` | `-7/16 Zeta[3]` |

The Meijer-convolution stage accepts a non-function result such as `0`. The Ramanujan
stage keeps its pFq inert, so a wrong-strip fallback can no longer fire.

## Machine-precision `Hypergeometric2F1` outside the disc answers a machine number ; v0.503

When the fast double kernel declines a machine argument outside the unit disc (off the
cut), the arbitrary-precision continuation now answers and the result is rounded to a
machine number, instead of the call staying unevaluated. `N[..., 20]` at such points now
evaluates too.

## MeijerG reduces to named functions; `FunctionExpand` of `PolyLog` at roots of unity ; v0.502

**MeijerG.**
- `MeijerG[{{1}, {}}, {{1/2}, {0}}, z]` gives `Sqrt[Pi] Erf[Sqrt[z]]`.
- Equal parameters in opposite groups cancel.
- G reduces on the unit circle when every series converges there.
- `FunctionExpand` recognises BesselK/HypergeometricU shapes in `1/z`, and gives a
  `Piecewise` over `|z| < 1` / `|z| > 1` for the p = q case.

**PolyLog.** `FunctionExpand[PolyLog[n, E^(I Pi r)]]` uses closed forms: the Bernoulli
part always, plus Zeta multiples, ±Catalan, or PolyGamma terms. Conjugate pairs cancel
exactly, so `PolyLog[3, I] + PolyLog[3, -I]` gives `-3/16 Zeta[3]`. There are also closed
forms for `Log[w]`, `Log[1 + w]` and `PolyGamma[m, 1/2 | 1/4 | 3/4]`.

## HypergeometricPFQ: error-function, inverse-trig and Gauss closed forms ; v0.501

These closed forms now apply automatically, as in the reference:
- `1F1(a; a+1; z)` for half-integer and positive-integer `a`, giving Erf/Gamma forms;
- Kummer's `1F1(1; c; z)`;
- `2F1(1/2, 1; 3/2; z)` → ArcTanh/ArcTan, and `2F1(1/2, 1/2; 3/2; z)` → ArcSin/ArcSinh;
- Gauss's sum at `z = 1` for rational parameters.

## `Plus` and `Times` honour a cleared `Orderless` ; v0.500

After `ClearAttributes[Plus, Orderless]`, `b + a` stays `b + a`. Numbers still collect
into one leading term, and like terms combine only with the term just before them,
matching the reference. With the default attributes, behaviour and timing are unchanged:
the attribute is read once from the definition cached on the head symbol.

## `Dot` prints infix: `a . b` ; v0.499

`a . b` now prints as `a . b` instead of `Dot[a, b]`, at the parser's precedence and with
the reference's parenthesisation, e.g. `(a b) . c`, `a^2 . b`, `(a . b)^2`. Printed forms
re-parse to the same expression. `FullForm` is unchanged.

## `Definition` keeps `=` vs `:=`; a tag that is too deep gives `::tagpos` ; v0.498

Each stored rule now records whether it was immediate or delayed. `Definition[sq]` after
`area[sq[s_]] ^= s^2` prints `area[sq[s_]] ^= s^2`, not `sq /: area[sq[s_]] := s^2`.
Values print in the reference's order: own values, then up values, then down values.
`?name` now uses the same printer. A tag that occurs too deep in the left-hand side
raises `TagSetDelayed::tagpos` with the reference's text, and a refused `TagSetDelayed`
returns `$Failed`.

## `TakeLargest` / `TakeSmallest` break ties by position ; v0.497

Ties were broken by an uninitialised position field, and `TakeLargest` read from the top
of the sorted list, so the later key won. Both now sort by key, then by position, so the
earliest element wins a tie, as in the reference.

## `IntegerString[n, "Roman"]` ; v0.496

`IntegerString[2026, "Roman"]` gives `"MMXXVI"` (`0` gives `"N"`, and `4000` gives
`"MMMM"`). It shares one table with `FromDigits[s, "Roman"]`, and the two round-trip for
1..4999.

## Strings: `$n` expands anywhere in a regex rule's right-hand side; character-code encodings ; v0.495

`StringCases[s, RegularExpression[...] :> {"$1", "$2"}]` used to leave `"$1"`
unexpanded when the right-hand side was a list or a nested call. Every string in the
right-hand side is now expanded, for `StringReplace` too.

`ToCharacterCode[s, enc]` and `FromCharacterCode[codes, enc]` accept `"UTF8"`,
`"ISOLatin1"`, `"ASCII"` and `"Unicode"`: `ToCharacterCode["a\[Alpha]", "UTF8"]` gives
`{97, 206, 177}`. Unrepresentable characters give `None`, and a malformed UTF-8 byte
raises `$CharacterEncoding::utf8`.

## Principal value across a symbolic pole; `Refine` of `Re` of provably real terms ; v0.494

`Integrate[1/(x - a), {x, 0, 2a}, PrincipalValue -> True, Assumptions -> a > 0]` now
gives `0`: a single symbolic interior pole is accepted once it is proved simple.
`Refine` resolves `Re`/`Im` of provably real terms before ComplexExpand, so the
symmetric PV of `1/x` on `[-a, b]` comes out as `-Log[a] + Log[b]`, not
`-Log[a^2]/2 + Log[b^2]/2`.

## Integrate: improper `e^{-xt}/t^n` integrals; DiffUnderInt no longer hangs ; v0.493

`Integrate[Exp[-x t]/t^2, {t, 1, Infinity}, Assumptions -> x > 0]` hung past 60 s; it now
returns `E^-x + x ExpIntegralEi[-x]` in 0.1 s, and the parameter-free form returns
`1/E + ExpIntegralEi[-1]`.
- **Pole search.** Newton–Leibniz now solves for poles factor by factor and skips the
  never-zero `E^u` factors.
- **The hang.** Differentiation under the integral sign no longer tries base points
  outside the assumed range.
- **Messages.** That stage is now an internal probe, so its inner messages stay silent.
- **Timeouts.** A timeout inside a muted probe no longer leaves arithmetic warnings
  silenced for the rest of the session: `g_arith_warnings_muted` and the DiffUnderInt
  depth are registered with the TimeConstrained unwind registry.

## Integrate: King reflection only on a finite interval; the Beta strip is widened by log weights ; v0.492

King reflection substituted `x -> Infinity - x` on a half-line and raised a spurious
`Infinity::indet`; it now declines non-finite endpoints, so the Gaussian–Bessel integral
returns `E^(-b^2/(4p))/(2p)` silently. The Beta stage accepts the wider convergence
strip that a `Log[1-x]^j` weight allows, and takes a limit where substitution gives 0·∞:
`Integrate[Log[x] Log[1 - x]/x, {x, 0, 1}]` is now `Zeta[3]`.

## `Series` expands Gamma-family heads at their poles; Mellin removable points ; v0.491

`Series[Gamma[s], {s, 0, n}]` and the `PolyGamma`/`Beta` analogues now expand at poles,
so `Limit[Gamma[s] Sin[s], s -> 0]` evaluates. The Mellin stage used this to take the
limit at a removable point instead of evaluating a 0·∞ form unmuted. The value
`Integrate[E^-x Sin[x]/x, {x, 0, Infinity}]` is now `Pi/4`, with no spurious
`Infinity::indet`, so `Check[]` no longer takes its failure branch.

## Half-integer `StruveH` is elementary; `D` rules for `StruveH` and `StruveL` ; v0.490

`StruveH[k + 1/2, x]` reduces to elementary functions (DLMF 11.4.4/11.4.5):
`StruveH[1/2, x]` gives `Sqrt[2]/(Sqrt[Pi] Sqrt[x]) - Sqrt[2] Cos[x]/(Sqrt[Pi] Sqrt[x])`.
Orders −9/2 to 9/2 were checked against reference values. `D[StruveH[nu, x], x]` is now
`(2^-nu x^nu/(Sqrt[Pi] Gamma[3/2 + nu]) + StruveH[nu - 1, x] - StruveH[nu + 1, x])/2`, and
`StruveL` has the analogous rule.

## Nielsen `PolyLog` real values stay real; `D[PolyLog[n, p, z], z]` ; v0.489

`PolyLog[0, 2, 2.]` came back with a spurious `-6e-16 I`: a small integer power of the
complex logarithm went through `cpow`. Repeated squaring now keeps the result exactly
real, and scalar, list, NDArray and Compile all still share the one kernel.
`D[PolyLog[n, p, z], z]` now gives `PolyLog[n - 1, p, z]/z`.

## `HypergeometricU[-n, b, z]` terminates to a polynomial ; v0.488

For a non-positive integer `a`, Tricomi U is a polynomial (DLMF 13.2.7):
`HypergeometricU[-2, b, z]` now gives `b + b^2 - 2 z - 2 b z + z^2`. All-machine arguments
still take the double kernel.

## `DirichletL` over an Interval with exact endpoints ; v0.487

`DirichletL[5, 3, Interval[{1/2, 3/4}]]` used to stay unevaluated. Rational, BigInt and
MPFR endpoints are now rounded outward to the enclosing double and go through the existing
rigorous enclosure, giving `Interval[{0.231751, 0.336106}]`.

## `?Minimize` / `?Maximize` describe the current scope ; v0.486

The docstrings now list the supported problem classes and the actual special return
forms, and state that `TimeConstraint` bounds the whole call. They no longer promise a
not-attained form the engine never returns.

## `Minimize`/`Maximize`: TimeConstraint bounds the whole call; separable, simplified, many-inequality, open-pole and polyhedral fixes ; v0.485

- **TimeConstraint.** It now bounds the whole call. One wall-clock deadline is set at entry
  and clamps every internal probe. A per-top-level decline memo stops the evaluator from
  re-running a declined call. Previously each stage got a fresh budget, and a declined call
  was re-run, so a 30 s default could become minutes.
- **Separable objectives under a constant factor.** A halved 3-variable Styblinski–Tang
  went from 141 s (then unevaluated) to 15 ms. A constant multiplier is spread over the sum
  before the separable split, and a variable-free denominator is no longer treated as a
  rational objective.
- **Simplified exact optima.** The value and each coordinate take the smallest of the raw,
  `Together` and `Expand` forms: `{14 - 2 Sqrt[13], {x -> 2 - 2/Sqrt[13], ...}}`.
- **More than 6 inequalities.** The `MZ_MAX_INEQ = 6` cap is replaced by the sound KKT
  bounds: active sets of at most n regular, or n+1 singular. A 3-variable 0/1 knapsack
  now solves.
- **Pole on an open boundary.** The denominator's sign is proved on the region itself,
  not its closure: `Minimize[{(x^2+1)/(x+1), x > -1}, x]` gives `-2 + 2 Sqrt[2]`.
- **Polyhedral regions.** Boundedness of a linearly constrained region is decided by 2n
  linear checks. An exact LP dropped from 2.3 s to 15 ms, and an equality-constrained case
  from 5.1 s to 57 ms.

## Compiled `Chop` returns `+0.`, not `-0.`, for a chopped negative ; v0.484

The compiled lowering multiplied `x` by a 0/1 mask, so a chopped negative came back as
`-0.`. It now adds `0.`, which turns the sign-carrying zero into `+0.` and leaves every
unchopped value unchanged. The fix covers scalar, rank-1, packed and NDArray inputs.

## `Chop` with an exact tolerance compiles; the interpreter accepts any real tolerance ; v0.483

`Chop[x, 10^-6]` and `Chop[x, Pi/10^6]` used to fall out of `Compile[]`, because the
lowering accepted only a machine-literal tolerance. Any real-valued scalar tolerance now
lowers. The interpreter also accepts a symbolic numeric tolerance such as
`Chop[x, Pi/10^6]`, which it previously left unevaluated, so the two surfaces agree.

## Compile: `Boole` and the sign predicates lower, scalar and rank-1 ; v0.482

`Boole[pred]`, `Positive`, `Negative`, `NonNegative` and `NonPositive` now compile at
scalar and rank-1 array shapes, so `Total[Boole[Positive[v]]]` compiles whole instead of
sending the body to the interpreter. The array form uses a new element-wise loop that
applies each head's scalar lowering to every element and takes the result element type
from that lowering. Results match the interpreter exactly and come back packed. Open
`check-compile-coverage` gaps fall from 33 to 28.

## A definite `Integrate` that succeeds no longer emits `Integrate::nonelem` ; v0.481

- **The bug:** `Check[Integrate[Log[1 + a^2 x^2]/(1 + x^2), {x, 0, Infinity}, Assumptions -> a > 0], failed]` printed `Integrate::nonelem` and returned `failed`, although the integral evaluates to `Pi Log[1 + a]`. Because the message marks the evaluation as failed, `Check[]` gave a wrong answer.
- **Cause:** a definite integral first tries an antiderivative (Newton–Leibniz). That probe runs a complete top-level indefinite cascade, and its exit flushed the held `nonelem` message as soon as the cascade declined. A later definite stage then answered, but the message had already been emitted.
- **Fix:** `src/calculus/integrate.c` now wraps the definite driver (`integrate_definite_scoped`). While a definite integral is running, a `nonelem` message from an indefinite probe (or from the depth-0 method surface) is passed up to a definite-level payload instead of being printed. The outermost definite frame emits it only if the whole definite call declined, so a definite integral that really fails (`Integrate[x^x, {x, 1, 2}]`) still reports it as before, and indefinite declines are unchanged.
- **Tests:** `test_no_spurious_nonelem` in `tests/test_integrate_diffunderint.c` covers the reported integral and the Bose integral `x^3/(E^x - 1)` (no message, `Check` returns the value), a definite integral that genuinely fails (caught, and silenced under `Quiet`), and an indefinite `Exp[x^2] Sin[x]` (still caught).

## `Unprotect` takes effect on every builtin (issue #103) ; v0.480

- **The bug:** for 154 builtins (`Sin`, `Plus`, `Hold`, `Set`, `Table`, …), `Unprotect` returned the name as if it had worked, but `Attributes` still listed `Protected` and assignments were still refused. `ClearAttributes` on those symbols was ignored the same way.
- **Cause:** their attributes came from the static `builtin_attrs[]` table in `src/attr.c`, cached per symbol as `base_attributes`. `get_attributes` returned `base_attributes | attributes`, so a cleared bit was put back on every lookup. The other builtins set their attributes in their `_init()`, and `Unprotect` already worked for them.
- **Fix:** `builtin_attrs[]` is now only an initial seed. `attr_init` ORs it into `def->attributes` once, and that field is the only record. The `base_attributes`/`base_seeded` fields are gone, and `get_attributes_def` is a plain field read.
- **Unchanged:** the default `Attributes` of all 1,538 names in `Names["*"]` are identical before and after.
- **Tests:** three cases in `tests/test_clearall_remove_protect.c`: `Unprotect`/`Protect` round trips on `Sin` and `Hold`, defining `Sec[42]` after `Unprotect`, and `ClearAttributes`/`SetAttributes` on `Cos` and `Range`. The expectations were checked against WL.

## N-ary special functions over packed arrays and in Compile, any operand ; v0.479

- **Nielsen `PolyLog[n, p, z]` has a machine kernel**, `sf_nielsen_c` (new `src/special_functions/sf_machine_nielsen.c`):
  - **Methods:** the closed form for integer `n ≤ 0` (a polynomial in −Log(1−z) and 1/(1−z) under z d/dz), the Stirling and Miller series, and tanh-sinh quadrature, on the same domain as the interpreter.
  - **Fallback:** it declines where its own error estimate exceeds 2e-14, and the arb path answers.
  - **Surfaces:** the scalar builtin, the packed / `NDArray` map and `Compile` all call it (`REG_N(PolyLog)`), and agree bit for bit.
  - **Accuracy and speed:** over the 479-value grid it is within 6.1e-15 of 30-digit values, at about 17 µs a call.
  - **Signed zeros:** before this was settled, a real `z` gave `1.0 - z` an imaginary part of −0.0, so `clog` took the lower side of the cut; values were conjugated, or off by e^{2π} for a complex `p`. The kernel now forms 1 − z with a +0, and powers of a negative real take arg +π.
- **`Compile` takes the array in any one n-ary operand**. `LerchPhi[v, s, a]`, `PolyLog[v, p, z]` and `Hypergeometric2F1[v, b, c, z]` used to bail unless the array was last. `VKERNN_*` now carries the operand's position from the end in the high byte of `flags` (`NARYV_FLAGS`); the liveness, DCE and disassembler walks read the run length through `instr_run_len`. Two array operands in one call still bail.
- **Packed and `NDArray` operands of a Listable n-ary head are mapped in one pass** (`ndarray_map_nary`, evaluator step 4b). This covers `LerchPhi`, `PolyLog[n, p, z]`, `Hypergeometric1F1`/`2F1`, `HypergeometricU`, `WhittakerM`/`W`, `EllipticPi`, `LaguerreL` and `DirichletL`.
  - **Before:** each element was boxed into an Expr and evaluated on its own.
  - **Results:** they equal the boxed List element for element.
  - **Fallback:** an int64 buffer, or an element the kernel declines, takes the List path.
  - **Packed-aware:** registering an n-ary kernel now marks a Listable head packed-aware.
- **`check-compile-coverage` probes 3- and 4-argument calls**, with the array first, in the middle and last.
  - `LerchPhi`, `WhittakerM`, `WhittakerW` and `HypergeometricU` leave the baseline (37 → 33 open). They had been "reported, not enforced" because no probe could spell them.
  - The stale `Hypergeometric0F1`/`1F1`/`2F1` exemptions ("rewrites to HypergeometricPFQ") are removed, since all three compile.
- **Gates:** `check-nd-surfaces` and `check-array-exactness` pass, the latter with one more probe packed (267).
- **Tests:** `test_nary_surfaces` in `tests/test_mixed_numericalize.c`.

## Nielsen PolyLog beyond the unit disk and for non-integer p ; v0.478

`PolyLog[n, p, z]` stayed unevaluated for |z| ≥ 1 and for a non-integer `p`, where the reference evaluates. It now evaluates in exactly the reference's domain:
- the closed form for integer `n ≤ 0` (any `z`, any `p`);
- any `n` and `p` on the closed unit disk;
- `z = 1` for Re n > 0;
- |z| > 1 for integer `n ≥ 1` and `p`.

A non-integer `n` or `p` off the disk still stays unevaluated, as it does in the reference.

- **Methods** (arb, any precision):
  - the Stirling series for integer `p` and small |z|;
  - a generalized-power series via Miller's recurrence for any `p`;
  - tanh-sinh quadrature of the principal-logarithm integral (`nb_tanh_sinh`, new in `src/flint_num_bridge.c`), split at t = 1/z for a real z > 1.
- **Verification:** a 637-call grid against the reference agrees on which calls evaluate in every case. All 479 values are within 6e-15 of 30-digit quadrature; the reference's own machine values are off by up to 2e-6. The 25-, 30- and 40-digit checks agree with the reference to the requested digits.
- **Speed:** 1–3 ms a call at machine precision.
- **Deliberate difference:** `PolyLog[1, 2, 1.] = Zeta[3]`; the reference gives `Indeterminate`.
- **Tests:** `test_nielsen_continued` in `tests/test_mixed_numericalize.c`.

## Mixed exact and inexact arguments numericalize; the special-function numeric gaps closed ; v0.477

`Zeta[2., Sqrt[2]]` is now a number, as `Sin[2.]` is, and so is every special function given an inexact argument beside an exact irrational one. A sweep of 279 calls over every special function — all-machine, and with each argument in turn left as an exact irrational constant — was run against the reference. With the evaluator rule below already in, 42 calls still disagreed, all in heads that had no numeric path for those arguments at all. After the fixes below, two disagree, and they are a deliberate difference (`HarmonicNumber`, below). The new tests are in `tests/test_mixed_numericalize.c`; every expectation was verified against the reference.

### The evaluator rule

- When a `NumericFunction` builtin declines a call whose arguments are numbers, numeric quantities or Lists of them, with at least one inexact and at least one irrational exact argument, the evaluator calls it once more with the irrational arguments numericalized to the lowest precision among the inexact ones (machine precision being the floor). `numeric_mixed_args_call` (`src/numeric.c`) does this, and it is step 5a of `evaluate_step`.
- Integers and rationals are not converted, since they are often an index (`BesselJ[2, …]`, `ProductLog[1, …]`). `NHoldFirst` / `NHoldRest` positions are skipped. `Flat` heads keep their own contagion pass.
- A decline that emitted a message is not retried. A symbolic argument or a user-defined `NumericFunction` head leaves the call unevaluated, as in the reference.
- The rule fixed, among others:
  - `Zeta`, `BesselJ`/`Y`/`I`/`K`, `Gamma`, `Beta`, `PolyLog`, `Hypergeometric0F1`/`1F1`/`2F1`/`PFQ`/`U`, `ArcTan`, `Log[b, x]` and `Binomial`;
  - `Pochhammer`, `EllipticE`/`F`/`Pi`, `ExpIntegralE`, `HurwitzZeta`, `LerchPhi`, `Whittaker*`, `StruveH` and `MeijerG`;
  - the orthogonal polynomials.
- `Zeta[2.`30, Sqrt[2]]` gives 30 digits.
- Deliberate difference: `HarmonicNumber[Pi/3, 1.36]` evaluates. The reference evaluates the all-machine call but leaves the mixed one unevaluated.

### Heads that had no numeric path

- **`Surd` (new).** The real n-th root. Exact (`Surd[-8, 3] = -2`, `Surd[Sqrt[2], 3] = 2^(1/6)`), machine (`sf_surd_r`, shared by packed, `NDArray` and `Compile`) and MPFR.
  - Messages: `::noneg`, `::indet`, `::preal`, `::int`, `::argr` and `::argrx`.
  - An integer-valued real `n` is accepted (documented difference).
- **`KroneckerDelta` (new).** `NumericFunction` and `Orderless`. Identical arguments give 1, numeric arguments compare by `Equal`, and one unequal pair gives 0.
- **`Max` / `Min`** order real numeric quantities with the numbers and keep the winner exact: `Max[1, Pi] = Pi`, `Max[1., Pi] = Pi`. These stayed unevaluated before.
- **`HeavisideTheta` / `DiracDelta` with several arguments** (`src/internal/distributions.m`). A product: 0 or 1 by the signs. Positive arguments are dropped.
- **`StieltjesGamma`.**
  - `StieltjesGamma[n, a]` with an inexact `a` evaluates through arb.
  - `N[StieltjesGamma[3]]` evaluates. It used to give `StieltjesGamma[3.]`; the attributes now include `NHoldFirst`, which `N` honours.
  - `a ≤ 0` integer gives `ComplexInfinity`.
  - `StieltjesGamma::intnm` for a bad order.
- **`ExpIntegralE`** of any real, complex or arbitrary-precision order goes through arb's `acb_hypgeom_expint`. Before, only integer orders at machine precision evaluated. `E_s(0.)` for `s ≤ 1` is `ComplexInfinity`.
- **`PolyGamma` of non-integer order**, in the reference's Riemann–Liouville convention:
  - It was fitted to the reference's values and then confirmed to about 22 digits; arb's own generalisation differs.
  - It is a new arb kernel, `flint_num_polygamma_frac`.
  - Integer orders that the ladder declined now also fall to arb.
- **`LegendreP` / `LegendreQ` of general degree and order** use arb's `acb_hypgeom_legendre_p/q`.
  - Types 1 and 2 map to arb type 0; type 3 maps to arb type 1.
  - Checked inside and outside (-1, 1) and at complex `x`.
  - `N` of the four-argument form works; the type label `2.` is accepted.
- **`FactorialPower[x, n, h]`**, the step form, was never implemented.
  - It covers a positive integer, a negative integer or a non-integer `n` for numeric `x` and `h`.
  - `FactorialPower[5, -2] = 1/42` now evaluates.
- **`QPochhammer`.**
  - A non-integer `n` is `(a; q)_∞ / (a qⁿ; q)_∞`. A negative integer `n` is exact.
  - A complex or MPFR infinite product evaluates through arb; it used to be rounded to a double.
  - The machine path uses the shared kernel.
  - At (`Sqrt[2]/3`, 0.866, `Pi/3`) the reference is off by 1.3×10⁻¹⁴, confirmed with mpmath.
- **`BesselJZero`** was a placeholder that never evaluated.
  - It now evaluates for a real order `n > -1` with an inexact argument or under `N`.
  - Machine values use McMahon's expansion or a sign-change scan, then Newton (`sf_bessel_j_zero_r`, shared by packed, `NDArray` and `Compile`), and are within 3 ulp.
  - Arbitrary precision uses Newton in arb.

## Parser and matcher: `sym:patt` precedence (issue #102), and an exhaustive reference-graded matcher corpus ; v0.475

**Issue #102.** `MatchQ[f[1, 2, g[]], f[__, n_*a:_g]]` returned `True` and
`MatchQ[f[1, g[]], f[_, n_.*a:_g]]` returned `False`; the reference gives the opposite. The
cause was the **parser**. `:` was an ordinary low-precedence infix operator, so
`n_.*a:_g` parsed as `Optional[n_.*a, _g]`, a different and silently wrong
pattern. In the reference, `:` takes its left operand at **atom level**: the bare symbol
(`Pattern`) or blank token (`Optional`) right before it. `parse_colon_suffix`
(`src/parse.c`) now attaches `:` in `parse_primary`. A `colon_hold` marker stops
an inner token from claiming the `:` that ends a `sym:p` operand (`a:b:c` is
`Optional[a:b, c]`). This was checked against 100 forms from the reference and
all agree, except two that the reference rejects and Mathilda still accepts leniently. The
forms include `n x_:0` → `Times[n, x_:0]`, `x + a:_g == b` →
`Plus[x, a:(_g == b)]`, `x?f:_`, `x|a:b` and `x:a:b:c:d:e`. A parse of all 646
tracked `.m`/`.wl` files with the old and new binaries found no change in real
code.

**Exhaustive corpus.** `tools/gen_match_exhaustive_corpus.py` crosses 18
construct families with shared subject sets. The families are Blank and head
patterns, sequences, nonlinear names, `sym:p` with every operator, Optional and
defaults, Alternatives, PatternTest/Condition, Repeated, Except/HoldPattern/
Verbatim, (Orderless)PatternSequence, Longest/Shortest, literal number
structure, KeyValuePattern, Orderless/Flat/OneIdentity heads, query heads at
level specs, definitions, and parse shapes. A named pattern is asked through
`ReplaceList`, which pins bindings, backtracking order and completeness, not just
yes/no. **Every expected value comes from a reference kernel**, with each
case in a fresh context. That gives 11,385 gating cases
(`tests/match_exhaustive_corpus.m`, ctest `match_exhaustive_corpus_tests`, about
35 s). Another 413 known divergences are annotated report-only cases in
`tests/match_exhaustive_observe.m`. An ordering-only divergence keeps a gating
multiset twin (`Sort[ReplaceList[…]] === Sort[{…}]`). The runner's parent no
longer polls on a fixed 20 ms sleep, which had put a 20 ms floor under every
case (at least 6 s for the old 300-case corpus, which now runs in 1.4 s).

**Matcher bugs the corpus found, all fixed and checked against the reference:**
- **Alternatives:** a name in a branch that was not taken is bound to
  `Sequence[]` once the whole match succeeds (`1 /. (x_ | y_) :> {x, y}` is
  `{1}`). A later occurrence can still bind it.
- **`sym:p` backtracking:** the name is bound first and `p` is matched with the
  real continuation. Before, `ReplaceList[2 x, p:x_.*y_ :> …]` found one of
  three matches.
- **OneIdentity** applies only through Optional/defaults, as in the reference. Before,
  `h[x_]` matched `x`, `h[a, b]` (as `x -> h[a, b]`) and, under Flat, `h[]`, and
  `h[a]` matched twice. A Flat head no longer repeats its default match
  (`x_. + y_` against `a + x`).
- **Orderless:** a literal element takes only the first equal argument
  (`ReplaceList[o[a, a], o[a, x_] :> x]` is `{a}`).
- **OrderlessPatternSequence** matches a contiguous run at its own position, in
  any order, and its elements may be sequence patterns. Before, it matched any
  subset anywhere: `f[1, 2, 3]` matched `f[3, OrderlessPatternSequence[1, 2]]`.
  Four hand-written corpus rows had encoded that and were corrected.
- **`x__..`** and other variable-width repeats backtrack into their unit split
  through a continuation (`ReplaceList[f[a, a], f[x__..] :> {x}]` is
  `{{a}, {a, a}}`). The sequence commit step is shared (`seq_commit`).
- **Level specs:** a mixed spec like `{2, -1}` matched nothing in `Cases`,
  `Count`, `Position`, `DeleteCases` and `MemberQ`. One `in_level_spec` helper
  replaces five copies, and it walks `Depth` only when a bound is negative.
- **Redefinition:** an alpha-equivalent left-hand side replaces the rule
  (`f[x_] := x^2; f[y_] := y^3` is one rule). Each rule stores an alpha-invariant
  hash, so 3,000 distinct definitions cost the same as before.
- **Dispatch arity:** `PatternSequence`, `OrderlessPatternSequence`,
  `Longest`/`Shortest` and sequence-branch `Alternatives` arguments make a
  DownValue variable-arity. `q[PatternSequence[a_, b_], c_]` never fired before.
- **`OptionsPattern[{o -> v}]`:** inline defaults are used by `OptionValue`.
- The hand-written corpus row `1 /. (x_ | y_) :> {x, y}` → `{1, y}` had been
  written from memory and was wrong; it now expects `{1}`.

**Known, recorded, not fixed here.** The reference's `ReplaceList` enumeration under Flat
without OneIdentity wraps one-operand slices both ways and repeats matches.
Orderless enumeration *order* with Optional elements follows the reference's canonical
order, which sorts patterns after other expressions; Mathilda's `expr_compare`
does not (`Sort[{{2, x}, {1, 2 x}}]` also differs). SubValues
(`f[x_][y_] := …`) are not implemented. `SequenceCases` and `SequencePosition`
are missing.

## Number-theory review, batch 3: primes ; v0.472

This applies the DivisorSigma review to `Prime`, `PrimePi`, `NextPrime`, `PrimeQ`, `PrimeNu`, `PrimeOmega` and `PrimePowerQ`. Expectations come from the reference.

### Prime counting: a tuned Deleglise–Rivat

`PrimePi`'s `Automatic` method is now a properly tuned Deleglise–Rivat (`src/numbertheory/primecount.c`).
- **Tuning**: $y = \alpha x^{1/3}$ with $\alpha = 0.0008\ln^3 x$.
- **Trivial leaves** are counted rather than visited.
- **Easy leaves** come from the π table, and above √z only prime $m$ are walked.
- **Hard leaves** (only at levels with $p_{b-1} \le \sqrt z$) use a bitset sieve with monotone popcount sweeps in place of a Fenwick tree.
- **Quotients** come from a precomputed reciprocal with an exact correction.
- **The fix that made α > 1 correct**: the old easy-leaf formula $\varphi(v, b-1) = \pi(v) - b + 2$ is only valid for $v \ge p_{b-1}$; below $p_b$ the right value is $\varphi = 1$.

### Performance

The scalar builtin no longer builds and evaluates a `Times`/`Power`/`Plus` tree for a machine `k`.

- **Machine integer `k`.** The answer comes exactly from the factorisation, in int64 through the shared helper `ndint_divisor_sigma_i64`, or in GMP by a Horner sum. A negative `k` uses `sigma_-k(n) = sigma_k(n)/n^k`.
- **Machine real `k`.** The answer is computed in `double` by a Horner sum per prime. That is more accurate than the closed form it replaces: at most 5.8 ulp from a 40-digit reference over `n <= 3000`, where the closed form reached 31 ulp at `k = 3.7`.
  - **One deliberate difference from the reference:** `DivisorSigma[0., 6]` is now `4.`. The closed form gives `0/0`, so it was `Indeterminate`, here and in the reference.
- **Packed and NDArray `int64` buffers.**
  - The per-element kernel raises `p^k` once per prime instead of once per exponent step.
  - A large buffer now builds one table of smallest prime factors, at one byte per integer of range. It does this through a new optional whole-buffer arm on `NDBinaryKernel` (`whole_i`, used by `ndarray_map_binary`). The rule for when to build the table was measured: always below 4·10⁶; up to 5·10⁷ once the buffer has at least `4 sqrt(max)` elements; never above 5·10⁷. Before this, every element was factored by trial division, so the cost grew as N^1.5.
- **`Compile`.** The scalar form `DivisorSigma[k, x]` now lowers, to a new `OP_DSIG_I` that calls the same helper. When the helper declines, `OP_DSIG_I` bails to the interpreter unconditionally, so `IF_NOCHK` cannot waive the bail. DivisorSigma is out of the `check-compile-coverage` baseline.

## Correctness/performance: the v0.464 limitations closed; Reduce transcendental roots; InputForm round-trip ; v0.465

- **Reduce over the reals with transcendental breakpoints.** `Reduce` now solves univariate exp-trig-polynomial inequalities and equations whose roots `Solve` cannot find. It isolates the real roots with certified arb interval arithmetic on a provably bounded region and returns them as exact rationals or as transcendental `Root[{f, x0}]` objects. `Reduce[Sin[x] > x/2, x, Reals]` gives `x < Root[{#1 - 2 Sin[#1] &, -1.89549}] || 0 < x < Root[{#1 - 2 Sin[#1] &, 1.89549}]`, as the reference does. Infinitely many roots (`Sin[x] > 0`) or no provable bound still leaves Reduce unevaluated. `Root[{f, x0}]` is certified by interval Newton, refines to any precision under `N`, canonicalises x0 and its body, and gives `Root::invrt` for an x0 that is not at a root. A six-digit printed x0 reads back.
- **Reduce input normalisation.** `Not[a > b]` folds to `a <= b`, with De Morgan through `And` and `Or`, and over Reals a relation side carrying `Re`/`Im`/`Conjugate` is ComplexExpanded. A residual that vanishes on a whole interval (`ArcCos[1 - 2 x^2] - 2 ArcSin[x]` on [0, 1]) is decided cell by cell instead of burning the isolation budget. This restores `Refine[Cos[x] > 0, -Pi/2 < x < Pi/2] = True`, `Simplify[ArcCos[1 - 2 x^2] - 2 ArcSin[x], 0 < x < 1/2] = 0` and `Simplify[Sqrt[E^(2 I x)] - E^(I x), -Pi/2 < x < Pi/2] = 0`. All three had regressed in v0.464, which had removed the unsound one-sample shortcut that had decided them by luck.
- **Rules on ordered Flat heads are cheap again.** A failing rule on `**`, `Dot`, `And`, `Or` or a user `Flat` head paid a full match at every start offset after v0.462: seconds at n = 100 for `ff[x_, y_, x_]`, and n³ for `And[x_, Not[x_]]`. Offsets and spans that cannot match are now skipped using the pattern's first single-operand element as an anchor, and a group that cannot equal an already-bound name is rejected without being built. Repeated-name and anchored rules now cost about what v0.461 did. `PatternSequence[...]` elements now also match interior runs.
- **FactorInteger: bignum Fermat and Lehman.** The Fermat residue filter tests 64 candidates per block with precomputed bit masks: 0.5 ns per value instead of 10 ns. The Lehman sweep gives k = 1 about 5/6 of each round, and a larger "Iterations" never finds less. Near-square factors are cheap again (NextPrime[10^25]·NextPrime[10^25+10^16] takes 2.5 ms, against 77 ms in v0.464), and ratio-3, 5/7 and 2/3 factors stay at a few ms. The default Lehman budget is now 2^28.
- **InputForm round-trips machine reals.** `InputForm`/`FullForm` and `ToString[_, InputForm]` print a machine real as the shortest decimal that reads back to the same double (6 digits before), with the machine mark `` ` `` on a 17-digit mantissa and `*^` exponents. A machine `*^` literal now parses with one correct rounding (`1.5*^-5` was one ulp off).
