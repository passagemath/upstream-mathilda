# Changelog: week of 2026-10-19 (Mon) – 2026-10-25 (Sun)

## Test: `primenu_tests` decline case was stale and took 1m45

`test_primenu_incomplete_factorisation_declines` expected `PrimeNu[NextPrime[10^40] NextPrime[10^41]]` to stay unevaluated, because FactorInteger used to abandon that number. The quadratic sieve now factors it in about 50 s per call. The test was therefore failing, correctly getting `2`, and spending 1m45 across its four calls. No input a unit test can afford still makes Automatic give up, since its ECM runs to 65-digit levels. The test now has two halves:

- **The guard, tested directly.** The validation loop of `df_factor_mpz` (`src/numbertheory/nt_gaussian.c`) is split out as `df_factor_list_read`, with no behaviour change. The test hands it a crafted incomplete factorisation `{{2, 3}, {composite, 1}}` and asserts it is refused with its outputs untouched. A mutation check (guard disabled) makes the test fail.
- **End to end, fast.** For `NextPrime[10^20] NextPrime[10^21]`, with both primes above 2^64, `PrimeNu`/`PrimeOmega`/`MoebiusMu`/`LiouvilleLambda` must give 2/2/1/1, the values Mathematica 14 gives. Before the original fix they gave 1/1/-1/-1.

The suite now runs in 0.85 s and passes.

## New builtin: `RandomPrime` ; v0.468

`RandomPrime[imax]`, `RandomPrime[{imin, imax}]`, `RandomPrime[range, n]` and `RandomPrime[range, {n1, ...}]` (`src/random.c`, `Protected`). Every semantic detail was checked against Mathematica 14: reversed bounds, `imin = 1`, `{}` dimensions, and the `noprime`/`intp`/`prmrng`/`posdim`/`argt` messages.

- **Exactly uniform over primes.** It rejection-samples from {2} ∪ {odd k in range}. Spans of at most 4096 enumerate their primes once. Wider machine spans need no existence scan, because the maximal prime gap below 2^64 is 1550. Bignum spans first scan for a witness prime, so an interval with no primes is reported rather than looping.
- **The same test as PrimeQ, by construction.** A new shared helper, `mth_is_prime_u64` / `mth_is_prime_mpz` in `src/facint.c`, is now what `PrimeQ` calls too. Below 2^64 it dispatches to the existing deterministic Montgomery Miller–Rabin (`fi_u64_is_prime`) instead of `mpz_probab_prime_p`. PrimeQ's answers are unchanged, since both are exact there, and machine-integer PrimeQ is cheaper.
- **Packed and fast.** Machine-width results are written straight into a packed int64 buffer. Against Mathematica 14 on the same machine: `RandomPrime[100, 10^6]` takes 8 ms vs 238 ms, `RandomPrime[{1, 10^18}, 10^5]` takes 0.43 s vs 6.9 s, and a 1024-bit prime takes 35 ms vs 72 ms.
- `tools/nd_fastpath_sweep.py`: `RandomPrime` was added to `SKIP_DIMS`, because it takes a dimension spec.
- Tests: ten new `test_randomprime_*` cases in `tests/test_random.c` cover ranges, shapes and packing, bignums, uniformity, seeding, `noprime` including the 1550-gap and `30! + 2..30` intervals, argument errors, and attributes. A cross-check runs `mth_is_prime_u64` against GMP for every n < 2·10^6, 10^5 random 64-bit n, and known strong pseudoprimes.

## Parser and matcher: `0..` and Repeated / RepeatedNull (issue #100) ; v0.467

`0..` was a parse error: the number lexer read `0.` as a real and left a stray `.`. `0...` silently became `Repeated[0.]`. Every expected value in the new tests comes from Mathematica 14.

- **Tokenization.** `..`/`...` win over a decimal point, so `0..` is `Repeated[0]`, `0...` is `RepeatedNull[0]`, `-1..` is `Repeated[-1]`, and `1..2` is `(1..)*2`. `1.5..` and `.1..` are unchanged. The same fix applies to precision literals: `2.5`10..` is `Repeated[2.5`10]`. Headed and sequence blanks now take the dots as the repeat operator: `{_Integer..}`, `x__..` and `_h...` were syntax errors. As in WL, a bare `_.` is still Optional, so `_...` is `(_.)..` and `_..` stays a syntax error. `Repeated[_]` now prints as `(_)..` so that it reads back.
- **Multi-argument units.** `{a, b, a, b}` now matches `{PatternSequence[a, b]..}` (it was `False`). The repeat bounds count units (`Repeated[PatternSequence[1, 2], {2}]` takes four arguments). `(PatternSequence[a, b] | c)..` and `{x__..}` work, with each repetition binding the same `x`. Fixed-width units are checked in one pass. The variable-width search is iterative and tries only feasible widths, so a failing match over 40 000 arguments takes milliseconds.
- **Sequence alternatives.** `MatchQ[{a, b, d}, {PatternSequence[a, b] | c, d}]` is `True`. Named alternatives (`x:(PatternSequence[a, b] | c)`) bind the consumed sequence.
- **Repeat specs.** `Repeated[p, -1]`, `Repeated[p, {a, b}]` and `Repeated[p, {2.5}]` used to match as if unbounded. They now issue `Repeated::range`, and `Repeated[p, {3, 2}]` and `Repeated[p, 0]` issue `Repeated::order`; all of them match nothing. The messages go through the message funnel, so `Quiet` and `Check` apply. A BigInt bound is treated as unbounded instead of overflowing an `int`.
- `Repeated` and `RepeatedNull` now have the `Protected` attribute.
- New suite `tests/test_repeated.c`, with 107 checks of WL-verified answers. `test_parse.c` gains `test_parse_repeated_tokens` and a print round-trip check.

## Parser: prefix `+` (issue #101) ; v0.466

`+x` was a parse error (`Unexpected character: '+'`); a leading `+` was only
accepted as the sign of a numeric literal. It now parses as in the Wolfram
Language, to a one-argument `Plus`, which the evaluator reduces to its operand:

- `+x` evaluates to `x`; `FullForm[Hold[+x]]` is `Hold[Plus[x]]`.
- The operand binds tighter than binary `+` and looser than `*`/`^`:
  `+a b` is `Plus[Times[a, b]]`, `+a^2` is `Plus[Power[a, 2]]`, and
  `+x == y` is `Equal[Plus[x], y]`.
- A signed literal is unchanged (`+5` is the integer `5`), as is `++x`
  (`PreIncrement`).

## Correctness/performance: the v0.464 limitations closed; Reduce transcendental roots; InputForm round-trip ; v0.465

- **Reduce over the reals with transcendental breakpoints.** `Reduce` now solves univariate exp-trig-polynomial inequalities and equations whose roots `Solve` cannot find. It isolates the real roots with certified arb interval arithmetic on a provably bounded region and returns them as exact rationals or as transcendental `Root[{f, x0}]` objects. `Reduce[Sin[x] > x/2, x, Reals]` gives `x < Root[{#1 - 2 Sin[#1] &, -1.89549}] || 0 < x < Root[{#1 - 2 Sin[#1] &, 1.89549}]`, as Mathematica does. Infinitely many roots (`Sin[x] > 0`) or no provable bound still leaves Reduce unevaluated. `Root[{f, x0}]` is certified by interval Newton, refines to any precision under `N`, canonicalises x0 and its body, and gives `Root::invrt` for an x0 that is not at a root. A six-digit printed x0 reads back.
- **Reduce input normalisation.** `Not[a > b]` folds to `a <= b`, with De Morgan through `And` and `Or`, and over Reals a relation side carrying `Re`/`Im`/`Conjugate` is ComplexExpanded. A residual that vanishes on a whole interval (`ArcCos[1 - 2 x^2] - 2 ArcSin[x]` on [0, 1]) is decided cell by cell instead of burning the isolation budget. This restores `Refine[Cos[x] > 0, -Pi/2 < x < Pi/2] = True`, `Simplify[ArcCos[1 - 2 x^2] - 2 ArcSin[x], 0 < x < 1/2] = 0` and `Simplify[Sqrt[E^(2 I x)] - E^(I x), -Pi/2 < x < Pi/2] = 0`. All three had regressed in v0.464, which had removed the unsound one-sample shortcut that had decided them by luck.
- **Rules on ordered Flat heads are cheap again.** A failing rule on `**`, `Dot`, `And`, `Or` or a user `Flat` head paid a full match at every start offset after v0.462: seconds at n = 100 for `ff[x_, y_, x_]`, and n³ for `And[x_, Not[x_]]`. Offsets and spans that cannot match are now skipped using the pattern's first single-operand element as an anchor, and a group that cannot equal an already-bound name is rejected without being built. Repeated-name and anchored rules now cost about what v0.461 did. `PatternSequence[...]` elements now also match interior runs.
- **FactorInteger: bignum Fermat and Lehman.** The Fermat residue filter tests 64 candidates per block with precomputed bit masks: 0.5 ns per value instead of 10 ns. The Lehman sweep gives k = 1 about 5/6 of each round, and a larger "Iterations" never finds less. Near-square factors are cheap again (NextPrime[10^25]·NextPrime[10^25+10^16] takes 2.5 ms, against 77 ms in v0.464), and ratio-3, 5/7 and 2/3 factors stay at a few ms. The default Lehman budget is now 2^28.
- **InputForm round-trips machine reals.** `InputForm`/`FullForm` and `ToString[_, InputForm]` print a machine real as the shortest decimal that reads back to the same double (6 digits before), with the machine mark `` ` `` on a 17-digit mantissa and `*^` exponents. A machine `*^` literal now parses with one correct rounding (`1.5*^-5` was one ulp off).
